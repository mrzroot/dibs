Call dibs on your edits.

ویرایش‌هایتان را رزرو کنید.

You fix a line by hand. Next turn, your AI agent quietly puts the old one back. dibs tells every agent what you changed since its last turn, stops edits that would undo your lines, restores them if one slips through, and keeps saying what is still not committed or pushed.

یک خط را دستی درست می‌کنید و ایجنت هوش مصنوعی در نوبت بعد بی‌صدا نسخهٔ قبلی را برمی‌گرداند. dibs به هر ایجنت می‌گوید از نوبت قبلش چه چیزی را عوض کرده‌اید، جلوی ویرایشی را که خطوط شما را برمی‌گرداند می‌گیرد، اگر چیزی رد شد آن را بازمی‌گرداند، و مدام یادآوری می‌کند چه چیزی هنوز کامیت یا پوش نشده است.

Agents don't see what you did between turns.

ایجنت‌ها نمی‌بینند بین دو نوبت چه کرده‌اید.

An agent remembers the file the way it last wrote it. When you tweak something in between, its next edit is built on a stale copy, so your change gets reverted, usually silently. It happens in every tool, and it is easy to miss until it ships.

ایجنت فایل را همان‌طور به خاطر دارد که آخرین بار نوشته است. اگر در این فاصله چیزی را تغییر دهید، ویرایش بعدی‌اش روی نسخهٔ کهنه ساخته می‌شود و تغییر شما معمولاً بی‌صدا برمی‌گردد. این در همهٔ ابزارها پیش می‌آید و تا به محصول نرسد به چشم نمی‌آید.

“The agent reverts my manual edits in between queries… This is a known issue.”«ایجنت ویرایش‌های دستی من را بین درخواست‌ها برمی‌گرداند… این یک مشکل شناخته‌شده است.»forum.cursor.com · user report and staff reply, paraphrasedگزارش کاربر و پاسخ تیم، نقل به مضمون
  1. claudewrites timeout=10می‌نویسد timeout=10
  2. youchange it to timeout=30به timeout=30 تغییرش می‌دهید
  3. youask: “add logging”می‌خواهید: «لاگ اضافه کن»
  4. clauderewrites the function from memory: timeout=10 is backتابع را از حافظه بازنویسی می‌کند و timeout=10 برمی‌گردد
  5. git3 files modified, branch never pushed. Nobody noticed.سه فایل تغییرکرده، شاخه هیچ‌وقت پوش نشده و هیچ‌کس متوجه نشده.
02 /

A journal, a brief, and a guard.

یک دفتر ثبت، یک خلاصه و یک نگهبان.

dibs init wires hooks into each agent you use. From then on every turn has a start and an end, so dibs knows which bytes the agent wrote and which ones you did.

dibs init هوک‌ها را به هر ایجنتی که استفاده می‌کنید وصل می‌کند. از آن به بعد هر نوبت شروع و پایان دارد، پس dibs می‌داند کدام تغییر را ایجنت نوشته و کدام را شما.

Attribution journal

دفتر انتساب

Every change is recorded with its author: you, or claude / codex / cursor / gemini / copilot / aider. Content is stored locally in .git/dibs, nothing leaves your machine.

هر تغییر با نویسنده‌اش ثبت می‌شود: شما یا یکی از ایجنت‌ها. محتوا به‌صورت محلی در .git/dibs ذخیره می‌شود و چیزی از دستگاهتان خارج نمی‌شود.

“Since your last turn” brief

خلاصهٔ «از نوبت قبلت»

At the start of each turn the agent gets a short diff of what changed under it, by you or by another agent, so it builds on the current file instead of its memory.

در شروع هر نوبت، ایجنت یک diff کوتاه از تغییرات تازه (کار شما یا ایجنتی دیگر) می‌گیرد تا روی فایل فعلی کار کند، نه روی حافظه‌اش.

Revert guard

نگهبان بازگشت

Before an edit is applied, dibs checks whether it would drop a line you added or bring back one you deleted. Claude Code asks you; other agents are told no, with the reason.

پیش از اعمال ویرایش، dibs بررسی می‌کند که آیا خطی را که شما اضافه کرده‌اید حذف می‌کند یا خطی را که حذف کرده‌اید برمی‌گرداند. Claude Code از شما می‌پرسد و بقیهٔ ایجنت‌ها با دلیل رد می‌شوند.

Surgical restore

بازگردانی دقیق

If a revert slips through (a shell sed, a pasted file), dibs restore puts back only your lines and keeps the rest of the agent's work.

اگر بازگشتی از دست در برود (مثلاً sed در شل)، dibs restore فقط خطوط شما را برمی‌گرداند و بقیهٔ کار ایجنت را نگه می‌دارد.

Sync status

وضعیت همگام‌سازی

Uncommitted files, unpushed commits, branches that never reached a remote, stashes, repos with no remote at all, shown to you and to the agent.

فایل‌های کامیت‌نشده، کامیت‌های پوش‌نشده، شاخه‌هایی که هرگز به ریموت نرسیده‌اند، stashها و مخزن‌های بدون ریموت؛ هم به شما نشان داده می‌شود هم به ایجنت.

Blame for who, not when

blame برای «چه کسی»

dibs blame shows, per line, whether you or an agent wrote it, even before anything is committed.

dibs blame برای هر خط نشان می‌دهد شما نوشته‌اید یا یک ایجنت، حتی پیش از هر کامیت.

03 /

Try the revert guard.

نگهبان بازگشت را امتحان کنید.

This is the same check dibs runs before an agent's edit, ported to JavaScript. Edit any box; the verdict updates as you type.

این همان بررسی‌ای است که dibs پیش از ویرایش ایجنت انجام می‌دهد، به جاوااسکریپت منتقل شده. هر جعبه را ویرایش کنید؛ نتیجه همزمان به‌روز می‌شود.

04 /

One init, every agent.

یک init برای همهٔ ایجنت‌ها.

dibs detects which tools a repo uses and writes their native hook config. Existing hooks are kept; dibs uninstall removes only its own entries.

dibs تشخیص می‌دهد مخزن از چه ابزارهایی استفاده می‌کند و تنظیمات هوک بومی همان ابزار را می‌نویسد. هوک‌های موجود حفظ می‌شوند و dibs uninstall فقط ورودی‌های خودش را حذف می‌کند.

“MCP + rules” means the agent is asked to call the dibs tools; it is guidance, not enforcement. The git pre-commit guard still applies to everyone.«MCP + قواعد» یعنی از ایجنت خواسته می‌شود ابزارهای dibs را صدا بزند؛ این راهنمایی است، نه اجبار. نگهبان pre-commit گیت برای همه فعال است.

What isn't on GitHub yet?

چه چیزی هنوز روی گیت‌هاب نیست؟

dibs status answers it in one screen: who changed what, which agent edits undid your work, and what would be lost if this laptop died now.

dibs status در یک صفحه جواب می‌دهد: چه کسی چه چیزی را تغییر داده، کدام ویرایش ایجنت کار شما را برگردانده، و اگر همین حالا لپ‌تاپ خراب شود چه چیزی از دست می‌رود.

  • 1Uncommitted, staged and untracked filesفایل‌های کامیت‌نشده، stage‌شده و ردیابی‌نشده
  • 2Commits ahead of upstream, and branches never pushedکامیت‌های جلوتر از upstream و شاخه‌هایی که هرگز پوش نشده‌اند
  • 3No remote configured, detached HEAD, forgotten stashesنبود ریموت، HEAD جداشده و stashهای فراموش‌شده
  • 4The same line goes into every agent brief, so agents remind you tooهمین خط در خلاصهٔ هر ایجنت هم می‌آید تا ایجنت‌ها هم یادآوری کنند

Sixty seconds to set up.


راه‌اندازی در شصت ثانیه.


Python 3.9+ and git. No daemon, no account, no network calls.


پایتون ۳٫۹ به بالا و گیت. بدون سرویس پس‌زمینه، بدون حساب کاربری، بدون تماس شبکه.











1Init in your repoinit در مخزن
dibs init detects your agents, or name them: dibs init --agents claude,cursor.
dibs init ایجنت‌ها را پیدا می‌کند، یا نامشان را بدهید: dibs init --agents claude,cursor.


2Work as usualمثل همیشه کار کنید
Edit by hand, prompt agents, switch tools. dibs records each turn through the hooks.
دستی ویرایش کنید، به ایجنت‌ها دستور بدهید، ابزار عوض کنید. dibs هر نوبت را از طریق هوک‌ها ثبت می‌کند.


3Check before you leaveپیش از رفتن بررسی کنید
dibs status, then dibs restore if anything of yours was undone.
dibs status و اگر چیزی از کارتان برگشته بود dibs restore.

How it compares


مقایسه با ابزارهای دیگر


Attribution tools tell you afterwards who wrote a line. Checkpoints let you roll a whole turn back. dibs acts during the session, before your work is lost.


ابزارهای انتساب بعداً می‌گویند چه کسی خطی را نوشته. چک‌پوینت‌ها کل یک نوبت را برمی‌گردانند. dibs در حین کار عمل می‌کند، پیش از آنکه کارتان از دست برود.
