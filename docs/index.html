dibs stops AI coding agents from undoing what you typed.

Agents don't see the edits you make between their turns, so they "fix" them back. dibs tells them what you changed, blocks the revert before it lands, and restores only your lines if one slips through.

One turn, both sides of the seam

  

    
01
You edit by hand
Between turns you change timeout=10 to timeout=30. dibs records it as yours — with the lines, the time, and the file.

    

    
The agent gets a brief
[dibs] Since your last turn these files were
changed outside your session — by the human, by hand.
• api.py — edited by human (+1 −1, 2m ago)
    - r = requests.get(url, timeout=10)
    + r = requests.get(url, timeout=30)

  

  

    
02
It tries anyway
Before any edit runs, dibs checks whether it removes lines you added or brings back lines you deleted. Claude Code asks you; Codex, Gemini and Cursor get a denial that names your lines.

    

    
The edit bounces
dibs: this edit to api.py would undo changes the
human made by hand.
It removes lines the human added or changed:
  + r = requests.get(url, timeout=30)
Keep the human's version and make your change
around it.

  

  

    
03
Something slipped through?
A sed in a shell command, or an agent with no hooks. dibs sees it right after, tells the agent, blocks the commit, and puts back only your lines.

    

    
Your lines come back
$ git commit -m "add logging"
dibs: this commit contains files where an AI agent
undid lines you edited by hand:
  #7 api.py (claude): r = requests.get(url, timeout=30)
$ dibs restore api.py
✓ restored the human lines in api.py (undoing #7)
